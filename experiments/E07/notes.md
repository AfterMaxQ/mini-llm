## 只保存权重，少了什么？

适配器权重能恢复模型当时的行为，但优化器还记着过去梯度的统计量，数据顺序也推进到了某个位置。dropout 又会使用随机状态。如果这些没有恢复，看起来还是同一个 checkpoint，实际已经开始了另一条训练轨迹。

E06 的保存内容包括适配器、tokenizer、优化器、更新步数、当前数据顺序与位置，以及 Python、CPU 和 CUDA 的随机状态。本轮读取这些真实文件，不靠重新设一个 seed 来代替完整恢复。

拿到保存的 state 后，恢复优化器和随机状态的核心是：

```python
optimizer.load_state_dict(state["optimizer"])
rng.setstate(state["python_rng"])
torch.set_rng_state(state["torch_rng"])
torch.cuda.set_rng_state_all(state["cuda_rng"])
order, cursor = list(state["order"]), state["cursor"]
```

order 和 cursor 记录下一次该用哪个训练单元；只有恢复 seed，而没有恢复这两个值，下一步就可能用到不同的数据。

## 这个结果能保证多大范围？

它证明当前单 GPU、这批数据和这一步更新能够恢复并重放；没有据此保证换驱动、换设备或多卡以后仍逐位相同。加载输出的逐字比较也只覆盖首条任务，完整 32 条拟合结果由 E06 的逐条检查支撑。

复习问题的参考解释：相同 seed 只能给出随机序列的起点，不能代替中途已经推进的状态；只有模型权重相同，也不能保证下一次 AdamW 更新相同，因为优化器内部统计量可能不同。
