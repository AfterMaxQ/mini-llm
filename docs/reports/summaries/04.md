# 先把评测口径弄清，再比较模型

本册围绕部署后还能保留多少能力展开：合并与GGUF转换是否改变输出，量化能省多少显存，长上下文和并发是否稳定，以及模型能否在工具任务中正确决策。已执行的准备检查先归入本册，模型实验的结果到齐后再归纳比较。

目前BFCL已冻结13类、3,641条题目，其中AST题2,501条，相关性判断1,140条。29个手写接口样例实际走过官方handler和检查器，两个准备失败也保留了原始记录。模型尚未在这份清单上生成回复，因此这里没有BFCL模型成绩。

这一阶段先学到的是怎么解释分数：Java/JavaScript整数需要符合该版本检查器的表示方式，损坏的工具调用又可能被当成没有调用。正式评测要把官方类别成绩与解析异常并排看，不能只报一个混合准确率。
