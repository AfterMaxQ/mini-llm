# 从提示词基线走向正式微调

原模型在相同完整 dev 上，零样本通过 268/500，加入三条固定示例后通过 355/500。少样本提示提高了调用轮表现，也增加了本该询问或不调用时的误调用。后续模型都沿用这个已冻结的提示。

最近完成的 E09 规模组 E09-R16 使用 10,000 条训练轨迹，完整 dev 通过 411/500；调用轮为 494/568，不调用轮为 334/360。loss 与实际工具决策分开看，不能把更容易生成调用当成任务成功率提升。

10k 三个 seed（17、42、2026）分别通过 409、410、411/500；不调用轮落在 334—338/360。三轮在同一份 dev 上完成，不能当作独立测试集成绩。

精度对照沿用同一生成后端和完整 dev：NF4 训练组通过 406/500，BF16 训练组通过 403/500；调用轮分别为 482/568 与 468/568，不调用轮为 342/360 与 349/360。三条轨迹的差异说明这批结果接近，不能据此单独断言精度优劣。

训练中遇到的 LoRA 重复准备和显存缓存问题，连同处理过程与失败条件都保留在正文。各组效果按自己的冻结数据与验证条件比较；最终配置只由 dev 选择，test 留作独立检查。

rank 对照使用同一份 5k 数据，学习率对照另在同一份 1k 数据上固定 rank 16。两组各自使用相同的验证清单和保存规则，分开比较；配置选择只使用 dev。

1k 学习率组在固定 100 条 dev 上，1e-4 通过 68/100，5e-5 通过 63/100；调用轮分别为 86/112 与 84/112，不调用轮为 59/72 与 56/72。按预先确定的整条轨迹通过数选择 1e-4。这个结论限定在该冻结子集和单次训练 seed。

数据质量准备保留 5k 筛选池与阅读抽查，训练比较使用来源和类别匹配的两份 1k 数据。规则的误删和漏检、筛选成本、监督量与模型表现分别记录，效果不能由“通过筛选”直接推出。

在同一份 100 条 dev 上，额外筛选组通过 78 条轨迹，基础组通过 68 条；差异主要出现在逐轮“不调用”判断。两组只有一个训练 seed，筛选组还替换了部分样本，因此这 10 条差距说明本次筛选数据表现更好，不能单独证明筛选规则带来了因果提升。
