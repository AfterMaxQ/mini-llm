# 从提示词基线走向正式微调

原模型在相同完整 dev 上，零样本通过 268/500，加入三条固定示例后通过 355/500。少样本提示提高了调用轮表现，也增加了本该询问或不调用时的误调用。后续模型都沿用这个已冻结的提示。

10,000 条训练轨迹的最佳 dev 结果为 411/500，较固定示例基线多 56 条。三个 10k seed 落在 409—411/500；不调用轮为 334—338/360，低于 5k 的 342/360。规模与 seed 队列已完成，但这些仍是同一份 dev 上的成绩，不能替代独立 test。loss 和工具决策分开看，不能把更容易生成调用当成任务成功率提升。

LoRA 重复准备和验证阶段的显存缓存问题已经找到处理办法，失败条件与经过保留在正文。下一步转向相同数据、rank、训练步数和提示条件下的 BF16 LoRA/QLoRA 对照，再开展 rank、学习率与数据质量实验；最终配置仍不能由 test 选择。

rank 对照固定学习率，选定 rank 后再比较学习率。候选参数量来自真实权重形状，训练与工具表现按当前章节分别记录，配置选择只使用 dev。

数据质量对照按来源和类别匹配两份 5k 数据，逐条复查也保留了规则误删和漏检。筛选成本、监督量与后续模型表现分开记录，效果不能由“通过筛选”直接推出。
