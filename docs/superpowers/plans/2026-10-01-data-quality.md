# E12：等量数据质量对照

E12 比较训练数据的选择方法。原 5k 筛选池与阅读抽查完整保留，正式训练各用来源和类别匹配的 1k 数据，同一份固定 100 条 dev；所有冻结样本均进入分母。

- [x] 冻结额外筛选规则，再扫描数据。规则检查调用参数的表面来源与工具返回中的明确占位文本；不声称公开工具已经真实执行。
- [x] 读取 E02 已保存的任务组划分，重建原有训练区每组的同一代表样本。前 10,000 条须与冻结训练文件逐条一致；dev/test 不进入筛选和抽查。
- [x] 以原 5,000 条为参考，按“来源 × 类别”配额选取 5,000 条通过筛选的独立轨迹。配额不足就记录失败，不放松规则、不删除类别。
- [x] 保存每条筛选理由、参数出处、样本差异、耗时和来源哈希。随机复查 25 条保留和 25 条剔除样本，说明误删和未检查的语义问题。
- [x] 用原有模板、当前回复监督遮罩展开新数据，在 CPU 核对回复单元、监督 token、最大长度与无截断条件。冻结新训练文件与原 dev 的哈希。
- [x] 更新中文笔记、来源与类别图表、阶段总结及证据索引；Word 原生导出 PDF 并查看新增或变化页面，归档并推送。
- [x] 从筛选池冻结 1k 数据，逐项匹配原 1k 的来源与类别数量，保存 id 和文件哈希。
- [ ] 使用 `configs/quality.json` 训练额外筛选数据；rank 16、学习率 1e-4、seed 17、一个 epoch，复用 E11 同协议的 1k 基础组。初始、每 200 步和末步计算固定 dev loss，最终用固定提示评测全部 100 条冻结轨迹。
- [ ] 比较配对 dev 结果、调用/不调用、长度与监督量、显存和耗时。结论同时考虑筛选方法和样本内容变化；负结果如实保留。

同样的独立轨迹数与一个 epoch 不意味着相同的回复单元数、更新步数或监督 token 数，这些差异单独报告。数据规则不读取 dev 成绩，也不根据最终 test 调整。数值检查用于核对真实实验，不建立 TDD 或额外任务平台。
