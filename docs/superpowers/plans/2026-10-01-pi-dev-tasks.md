# Pi dev 任务准备与执行计划

当前主 Agent 按已批准 spec 直接执行，不使用子 Agent，不采用 TDD。

目标是补齐40个dev场景，八类各5个。使用8个新的模板与仓库族，每族5个不同内容的场景；不能写成40个不同模板。共享任务判据和Pi工具适配，参考过程与模型生成分开记录。最终100个test任务仍另建任务族，在模型方案选择前冻结，不从这40个场景改几个参数获得。

## 本轮任务结构

| 类别 | dev任务处理的问题 | 与训练区的区别 |
| --- | --- | --- |
| 读取定位 | 按功能开关与路由表找到当前处理函数 | 选择依赖两个开关，不根据同名旧模块回答 |
| 配置修改 | 按租户和通道定位数组中的订阅项 | 更新特定行，保留其他行及数组顺序 |
| 函数修复 | 解析含引号、逗号、转义引号和尾部空列的CSV行 | 状态转换问题，覆盖多种字段边界 |
| 多文件修改 | 同步具名导出、转发入口和调用方的API名称 | 检查实际导入链与运行结果 |
| 失败恢复 | 处理异步格式化函数未被等待的错误 | 保留失败命令，检查正常返回与异常传播 |
| 缺信息询问 | 两个租户都可匹配时询问目标租户 | 不按列表第一项猜目标，不擅自写配置 |
| 无需工具 | 按已给定义计算最近秩法p95 | 只根据给出的20个测量值回答，不读取文件 |
| 路径恢复 | 从缺失旧报告恢复到最近成功快照 | 按状态和日期选择，再统计当前报告 |

## 文件与步骤

- [x] 新建 `configs/pi-dev-tasks.json` 和 `scripts/pi_dev_probe.mjs`。同一入口先核对训练模板/仓库族与精确场景重复，再逐个用两个独立容器运行错误候选和参考过程。
- [x] 保存40个实际场景、逐条事件、最终文件、判据和工具预算；参考全部通过且初始/明确错误候选全部被拒绝后才冻结dev清单。运行失败另开编号，不修改失败记录。
- [x] 对原始数据复核分母、任务族、哈希、调用返回和清理结果。检查全文输入是否超过8192；只核对token，不启动模型或占用GPU。
- [x] 整理真实结果与失败例子，更新Markdown、索引和Word，实际导出PDF查看全部页面。

配置沿用Pi 0.99.1与已固定容器镜像；无网络、无宿主挂载、无GPU请求。工具最多12次、命令60秒、单任务300秒、上下文8192。失败和截断不能从正式任务分母中删除。

8个模板族属于同一自编任务集，参数变体的相关性需要在最终分析中说明；除了按任务的重复运行统计，另展示各模板族表现。当前不调用教师或学生，也不将规则参考通过率当成Agent成绩。
