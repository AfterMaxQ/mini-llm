# Pi 参考任务与成功判据

先核验任务本身，再让模型运行。当前 GPU 队列继续执行，本计划的准备步骤只使用本机 CPU 与无网络任务容器。

- [x] 为八类任务各建立一个训练区原型：读取定位、配置修改、小函数修复、多文件一致性、失败恢复、缺参数询问、无需工具回答、无效路径恢复。使用完整小项目及干扰文件，保留可读需求。
- [x] 参考操作由任务规则给出，调用 Pi 原始四工具并保存实际返回；它们是规则执行轨迹，不是教师输出或模型成绩。
- [x] 成功判据检查最终文件、运行输出、未授权改动及必要的回复。执行检查不依赖模型自述，检查脚本与无关文件不能被修改。
- [x] 同一判据分别检查初始状态、明确错误候选和正确参考操作；保留实际失败原因。每个任务最多 12 次调用，沿用 60 秒命令、300 秒任务时限。
- [x] 整理真实请求数、判据结果、失败例子及来源哈希，归档并写入第二册；Word 导出 PDF 后实际查看变化页面，再提交推送。
- [x] 将已执行原型转换为多轮训练记录，逐个核对调用与返回、官方模板文本、token 和当前回复监督位置；记录完整长度，不截断调用。该格式核验不替代正式轨迹数量和 GPU 训练。
- [ ] 在训练区扩展任务模板和仓库结构，实际取得至少 1,000 条有效参考轨迹；教师生成另准备至少 2,000 个训练请求，不复制补量。
- [ ] 分别建立 40 个 dev 与 100 个最终 test 任务。模板族和仓库族不跨划分；不能仅换变量名或参数就把同一模板算作独立新任务。test 八类至少各 10 个，额外 20 个分给函数修复、多文件修改、失败恢复和路径恢复，各 5 个。
- [ ] E09—E12 完成后进行真实模型 Pi 接入及迁移比较，记录任务级结果与通用回归，再继续教师验证和匹配蒸馏。

八个原型全部属于训练区，不是正式 dev/test 子集。八个成功原型也不满足 E14 正式规模；后续扩展记录任务结构、执行成本和真实有效数。测试失败恢复任务中的检查代码属于任务成功判据，不引入 TDD 流程。
