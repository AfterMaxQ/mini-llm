# Pi 参考任务与成功判据

先核验任务本身，再让模型运行。当前 GPU 队列继续执行，本计划的准备步骤只使用本机 CPU 与无网络任务容器。

- [x] 为八类任务各建立一个训练区原型：读取定位、配置修改、小函数修复、多文件一致性、失败恢复、缺参数询问、无需工具回答、无效路径恢复。使用完整小项目及干扰文件，保留可读需求。
- [x] 参考操作由任务规则给出，调用 Pi 原始四工具并保存实际返回；它们是规则执行轨迹，不是教师输出或模型成绩。
- [x] 成功判据检查最终文件、运行输出、未授权改动及必要的回复。执行检查不依赖模型自述，检查脚本与无关文件不能被修改。
- [x] 同一判据分别检查初始状态、明确错误候选和正确参考操作；保留实际失败原因。每个任务最多 12 次调用，沿用 60 秒命令、300 秒任务时限。
- [x] 整理真实请求数、判据结果、失败例子及来源哈希，归档并写入第二册；Word 导出 PDF 后实际查看变化页面，再提交推送。
- [x] 将已执行原型转换为多轮训练记录，逐个核对调用与返回、官方模板文本、token 和当前回复监督位置；记录完整长度，不截断调用。该格式核验不替代正式轨迹数量和 GPU 训练。
- [ ] 在训练区扩展任务模板和仓库结构，实际取得至少 1,000 条有效参考轨迹；教师生成另准备至少 2,000 个训练请求，不复制补量。
- [ ] 分别建立 40 个 dev 与 100 个最终 test 任务。模板族和仓库族不跨划分；不能仅换变量名或参数就把同一模板算作独立新任务。test 八类至少各 10 个，额外 20 个分给函数修复、多文件修改、失败恢复和路径恢复，各 5 个。
- [ ] E09—E12 完成后进行真实模型 Pi 接入及迁移比较，记录任务级结果与通用回归，再继续教师验证和匹配蒸馏。

八个原型全部属于训练区，不是正式 dev/test 子集。八个成功原型也不满足 E14 正式规模；后续扩展记录任务结构、执行成本和真实有效数。测试失败恢复任务中的检查代码属于任务成功判据，不引入 TDD 流程。

## 第二批训练模板

沿用现有任务容器、Pi 四工具和判据，新增八个训练模板族：注册表选择实现、分层配置覆盖、保留最后出现位置的去重、时间单位迁移、移动模块的导入恢复、未给时区的提醒、已知速率的预算计算、按商品状态联表统计库存。旧原型保持原记录；新增任务全部属于 train，模板和仓库族不进入 dev/test。

每个任务先检查初始错误，再在同一控制容器执行一个具体错误方案，最后用新容器执行规则参考。分层配置的错误方案改默认值，多文件迁移的错误方案只改字段名，去重的错误方案倒序并修改输入。保留实际返回、最终文件和拒绝理由；核验结束后归档并归纳进现有章节，不把16个模板写成1,000条有效轨迹。

- [x] 执行新增八个模板的初始、错误方案与参考检查。
- [x] 逐条复核事件、最终文件、隔离设置和容器清理，保存文件清单与哈希。
- [x] 整理真实差异及失败例子，核验 Word 变化页面后提交推送。

新增参考执行后，沿用已核验的官方模板与当前回复监督规则转换数据。输入数量与调用数从真实来源读取；两类错误返回保留在历史中，逐个检查其后回复的遮罩。旧运行结果不改写，新转换另开运行号，保存输出清单与哈希，再整理实际长度和监督量。

## 正式训练场景与参考执行

从已验证的16个训练模板族生成2,000个训练场景，每族125个；变体改变实际配置、函数样例、当前实现、日期、速率和库存关系。所有变体留在train，按族保留来源，不能冒充独立的新模板。冻结时比较规范化的完整问题和文件内容，重复则整轮不通过；共享模板属于已知的近似重复，后续dev/test使用另外的模板与仓库族。

冻结清单前1,000个场景按原顺序执行规则参考，八类各125条。每个场景使用新的无网络容器，通过Pi原始工具执行，再检查最终文件与原检查。逐条JSONL落盘，参数、错误、最终状态和清理结果都保留；失败不移出目标分母。每10分钟替换当前进度章节，成功取得全部参考后再转换完整训练格式。CPU执行有独立进程锁，不启动模型或占用GPU。
