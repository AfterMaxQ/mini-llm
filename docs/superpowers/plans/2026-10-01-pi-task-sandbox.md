# Pi 任务容器与工具接入计划

由当前主 Agent 使用 superpowers:executing-plans 执行，不使用子 Agent，不采用 TDD。依据：[项目规格](../specs/2026-09-30-agent-training-lab-design.md) 中 E13—E14 的任务环境要求。

目标是让主机上的 Pi 0.99.1 使用自己的 read、edit、write、bash 定义，在独立 Docker 容器执行任务。工具链准备与模型 Agent 评测分别验收；工具执行通过不代表模型已经完成任务。

## 实现与核验

- [x] 用实际安装包检查四个工具的参数、返回和可替换 operations 接口；导出原始 schema 及来源哈希，不另写一套工具格式。
- [x] 在 `configs/pi-sandbox.json` 固定 Node 镜像 digest 和容器参数。容器无网络、无宿主目录挂载、根文件系统只读；任务文件使用独立临时文件系统，不注入凭据。
- [x] 实现 `scripts/pi_sandbox.mjs`：只替换 Pi 的文件与命令 operations，文件输入映射到任务工作区；检查规范化路径和实际父目录，拒绝路径越界及指向工作区外的符号链接。bash 在容器内执行，命令上限 60 秒，任务上限 300 秒。
- [x] 在真实容器实际运行 write、read、edit、bash，检查最终文件内容和执行结果；同时保留缺失文件、编辑不匹配、路径越界、符号链接、非零退出与超时的真实返回。
- [x] 核对 Docker inspect 的网络、挂载、只读与资源设置，并检查网络连接失败、根目录写入失败；保存调用、返回、最终状态、schema 和文件哈希，结束时只移除本次创建的任务容器。
- [x] 把执行前的工具核验写入 E13 主笔记和第二册，明确模型接入仍待执行。Word 实际导出 PDF，查看变化页，再归档和提交推送 main。
- [x] 已运行 E14-R26 固定 dev16，保存流式 tool_calls、调用 ID 与结果匹配及最终状态；16/16 个容器均回收，模型观察通过 0/16，14/16 个任务超时，超出每题 12 次执行预算的请求被拒绝。Pi test40 单独评测。

原始包、容器状态和长事件记录保存在本地归档，公共仓库保存适配代码、固定配置、必要 schema、精简结果与中文笔记。README、现有训练条件、数据划分和已结束运行的原始记录保持原样。
