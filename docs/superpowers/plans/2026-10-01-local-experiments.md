# MiniLLM 本机实验与记录执行计划

本计划按项目 spec 连续执行，由当前主 Agent 完成，不使用子 Agent，不采用 TDD。常规配置、排错、模型调整和归档无需用户干预。

## 1. 环境

工作目录为 F:/mini-llm-agent-lab。使用独立 Python 3.11 环境，PyTorch 2.8.0+cu128；Transformers 4.56.2、TRL 0.22.2、PEFT 0.17.1、bitsandbytes 0.47.0、Accelerate 1.10.1、Datasets 4.0.0、NumPy 2.2.6。安装后实际验证 CUDA 张量、反向传播和 NF4 运算，保存完整版本锁。

报告使用 python-docx、Matplotlib、Pillow、PyMuPDF 和 pywin32。BFCL 独立环境锁定 bfcl-eval==2025.12.17；Pi 项目内安装 0.99.1；llama.cpp 固定 b11292 Windows CUDA 12.4 构建与对应运行库，保存 SHA256。

原生 Windows 存在确认的兼容问题时，改用本机 Docker Linux GPU 容器，保持训练库版本并重跑 E01—E07。下载和 GitHub 推送允许联网；训练、教师生成、推理和评测均使用本机，不调用云模型或付费服务。

## 2. 实验顺序

| 阶段 | 实验 | 交付 |
| --- | --- | --- |
| 环境与数据 | E00—E02 | 环境证据、CUDA 验证、去重划分、至少 50 条样本检查 |
| 训练机制 | E03—E07 | token/mask、loss、梯度、32 条过拟合、保存恢复及第一册 |
| 正式微调 | E08—E12 | 提示基线、1k/5k/10k、LoRA/QLoRA、rank、学习率与质量对照 |
| Agent 与蒸馏 | E13—E18 | Pi 迁移、领域轨迹、教师验证、筛选和匹配蒸馏 |
| 推理与综合评测 | E19—E25 | 转换、量化、性能、BFCL、Pi、通用回归与误差分析 |

沿用 spec 的规模、初始训练参数和正式训练 seed 17、42、2026。非思考模式、assistant-only loss、packing 关闭。若模板不支持遮罩，只增加监督标记并验证渲染文本与 token 不变，不静默改为全文 loss。

每 100 optimizer steps 对完整验证集计算 loss，选择最低验证 loss 的 checkpoint，并列选择较早者；超参数使用完整 dev 工具表现选择，test 不参与选择。

Pi 主机端连接本地模型服务，read/edit/write/bash 在独立 Docker 任务容器执行。容器关闭网络，不挂载真实项目或凭据；保存工具 schema、调用、返回和最终状态。预算沿用 spec。

离线工具评测贪心解码；Pi 温度 0.2，每轮固定推理 seed，其余有效采样参数记录。BFCL 跑锁定版本全部 13 个 single_turn 类别，仅报告指定类别成绩；ARC-Challenge 官方 test 全集、零样本、统一 HF 评分后端。理解问题留作复习，不阻断实验，不代填掌握情况。

## 3. 模型调整

主学生 Qwen3-1.7B，教师先使用四位 Qwen3-8B，下载前锁定完整 revision。先释放本项目持有的模型、检查显存竞争和梯度检查点等配置；改变条件另开运行。

8B 教师无法在规定上下文稳定推理时改为 Qwen3-4B，重新进行教师 dev 验证。4B 学生扩展放在 1.7B 主线之后。若 1.7B 在正确环境仍有可复现资源限制，降为 Qwen3-0.6B并重新建立基线、微调和蒸馏对照。不同学生型号不合并提升幅度。

BF16 LoRA、长上下文和高并发的 OOM 保留为失败条件；其他实验继续。不能减少正式数据量、删困难任务或改变分母来制造完成。负结果可形成结论，未执行保持未完成。

## 4. 记录、归档与视觉核验

脚本、配置、实验笔记与精简结果、文档、本地大型产物分别组织；大型文件集中 `.local/`，现有准备记录迁入本地归档。

运行号使用 E编号-R编号，保存命令、配置、代码 commit/diff、模型和数据 revision、划分哈希、时间、退出码、指标与逐条结果。原始结果不覆盖。一份实验主笔记按问题、方法、过程、结果、理解、证据组织；Markdown 和 Word 使用同一份内容。

指标按日志频率写入。Word 在开始、关键变化、checkpoint、评测批次、报错和结束时更新，长任务至少每 10 分钟更新当前章节。分册目标 12—25 页，超过 30 页在实验边界拆分；阶段归纳保留关键失败与判断变化，最终总结 6—10 页。

临时 Word 快照保留最近 5 份，阶段结束保留最终和上一版。原始日志可压缩，指标、失败证据和关键 checkpoint 不参与临时清理；归档保存清单与哈希。

第一轮使用真实 E00 数据绘图并嵌入 Word；Loss 等待实际训练数据。Word 实际导出 PDF，渲染页面并查看图片；首次模板与每册定稿检查全部页，更新检查修改页。核对中文、图例、单位、表格、图注、分页和空白页。文件锁定时另存快照，不关闭用户 Word，未渲染不得标记已核验。

## 5. 验收和持续推进

实际 GPU 前向、反向、同步计时与显存输出是环境证据；机制通过才正式训练。汇总分母与逐条结果一致，失败、超时、截断、解析错误保留；Pi 按任务聚类分析，训练 seed 波动单独呈现。

脚本接受配置、运行目录与必要续跑参数，代码简洁且必要注释中文；不搭建额外任务平台。完成阶段或关键排错后归纳、更新索引、提交推送 main。README 只描述已验证入口。阶段之间自动继续，中断按保存记录恢复，只有本机无法解决的外部条件才报告阻塞。
