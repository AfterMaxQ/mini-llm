# E10：BF16 LoRA 与 QLoRA 对照执行计划

由当前主 Agent 使用 superpowers:executing-plans 执行；不使用子 Agent，不采用 TDD。

依据：[项目规格](../specs/2026-09-30-agent-training-lab-design.md)。目标是比较基础权重的存储精度对训练质量、显存与时间的影响，不能把入口准备完毕当成对照完成。

## 条件与边界

使用 E09 已冻结的 5,000 条轨迹、14,502 个回复单元、638,598 个监督 token；seed 17、rank 16、alpha 32、dropout 0.05、学习率 1e-4，训练一个 epoch，共 1,813 次更新。模板、监督位置、梯度累积、缓存释放和完整 dev 验证保持一致。每 100 步及末步验证全部 500 条 dev，按监督 token 加权选择最低 loss 的 checkpoint。

NF4 参考使用 E09 已完成的同条件 5k 运行及其完整 dev 工具评测。BF16 条件只改变基础权重存储与相应 PEFT 准备分支；实际基础权重、适配器 dtype 和可训练参数另外记录。两组适配器的工具生成都使用相同 NF4 推理后端、固定提示、贪心解码和 500 条 dev。这个质量比较回答训练方式的差异，BF16 推理的精度与速度留给推理实验。

PEFT 准备分支也可能改变适配器与非量化层的 dtype；报告比较两套实际方案，不把全部差异单独归因于四位编码。

先核对已有队列、配置中的 PID、进程创建时间、命令和 GPU 工作；E09 未结束时只做 CPU 准备。BF16 出现 OOM 时保留配置、完整堆栈、已完成指标和发生位置，不减少数据或上下文，不给失败条件填零成绩。已有同条件参考不重复训练。
